## 5 Most Serious FAILs

1. **A2 & A3: Missing Real Vision Model (`vision.pte`), No Accuracy Log, and Silent Fake Classifier Fallback**  
   Neither `vision.pte` nor any training accuracy benchmark log exists. In `ExecuTorchClassifier.kt:76-103`, when `vision.pte` fails to load, the app silently routes all camera scans through `SmartVisualClassifier` (a 364-line hard-coded color/pixel heuristic that fabricates crop and disease diagnoses).

2. **A6: Fake Llama Advisory Implementation**  
   `ExecuTorchLlamaAdvisor.kt:108-113` never imports or invokes ExecuTorch LLM native APIs (`LlmModule` / `LlamaModule`). It searches for `tokenizer.bin` (which is invalid for Llama 3.2's `tokenizer.model`) and unconditionally delegates advice generation to `FakeAdvisor`. Furthermore, the required ExecuTorch LLM Android library is missing from Gradle.

3. **A4: Hard-Coded Benchmark Metrics on Results Screen**  
   The benchmark card on `ResultScreen.kt:223-235` displays static string literals (`"Latency: ~114ms • RAM: ~138MB"` and `"100% Offline\n0 KB Network"`) rather than computing live execution timers or querying Android memory APIs, in direct violation of Rule H3 ("Never invent numbers").

4. **A9: `LeafValidator` Hard-Rejects Fruits, Pests, and Badly Diseased Brown Leaves**  
   `LeafValidator.kt:93-97` requires living green or chlorotic plant tissue (`(green + chlorosis) >= 0.04`). As a result, red tomato fruits, red chilli fruits, white cotton bolls, pests/insects, and severely necrotic brown leaves are rejected with a blocking popup dialog (`MainActivity.kt:147-155`), violating Requirement R2 ("leaf, stem, fruit or pest").

5. **A8 & A11: Hard-Coded UI Strings, Missing Trilingual XML Resources, and Missing Core Workflow Requirements**  
   `strings.xml` contains only the app name; no `values-te/strings.xml` or `values-hi/strings.xml` exist. All user-visible strings are hard-coded in Kotlin without language coverage unit tests. Key workflow requirements are missing: first-launch language selection buttons, region choice, "Sure / Probably / Not sure" UI certainty labels (raw percentage displayed instead), uncertain case referral, and the "Save case report to send later" screen.
